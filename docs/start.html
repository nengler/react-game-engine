Getting started

From an empty folder to a packaged game, in eight steps. Every command below was run, in this order, in a folder outside the engine's repository. Nothing is published to a registry yet, so the engine is installed from tarballs made by the repository.

0. What you need

  • Node 22.18 or newer (the compiler and the tools run TypeScript directly). That alone is enough to write, test and check a game.
  • A checkout of the engine's repository, once, to make the tarballs: npm install && npm run dist. This writes dist/packs/rge-*.tgz. It builds what your machine can, keeps going when a piece is missing, and ends by saying what you have and what to install for the rest.
You haveYou get
Noderge create and rge check: compile, type-check, tests, and a scripted run under Node
+ cmake and a C compiler (sudo apt install build-essential cmake; on macOS xcode-select --install and brew install cmake)Screenshots, and rge package --headless (the software renderer, no window)
+ the windowing libraries (libx11-dev libxrandr-dev libxi-dev libxcursor-dev libxinerama-dev libgl1-mesa-dev on Debian or Ubuntu)A window: rge dev with hot reload, and a packaged game that opens one
+ Rust (rustup.rs)rge package --engine quickjs (a few MB, no JIT), and rge check also plays the game under the Rust host and requires the same output

Run npm run dist again after installing something; the builds are incremental.

In VS Code, install the engine's extension once from the same checkout: npm run vscode:pack, then code --install-extension dist/rge-vscode-0.0.1.vsix. It shows the compiler's RGE errors in your components as you type, beside TypeScript's own, with quick fixes for the common ones (a missing import, useEffect(…, []) to useMount, useMemo to the value, <Text text=…> to children). It runs your game's own rge lsp, so other editors can use that as a language server for .tsx files.

1. Make a game

cd /path/to/engine && node packages/cli/src/cli.ts create ~/my-game --packs dist/packs
cd ~/my-game && npm install
npm run check

rge create copies the template. rge check compiles, type-checks, runs the tests, and plays a short scripted run under Node and under the Rust host, which must print the same. The template passes it before you change anything.

What is in the folder: package.json (its "rge" field names the entry and folders), main.ts (starts the player), game.ts (the root and the names a script may use), src/Main.tsx (the root), src/Hero.tsx (a component that keeps its own position and moves itself), src/GameState.ts (what the whole game shares), test/, assets/, parity.ts.

2. A moving square

npm run dev opens a window and hot reloads: save a file under src/ and the window changes, keeping the state. The template's src/Hero.tsx already moves a sprite with the arrow keys. It keeps its own position, as a React component keeps its own state:

export function Hero({ speed = 120 }: HeroProps) {
  const { x, y, move } = useBody({ x: 152, y: 82, width: 16, height: 16 });   // where it is: state
  useUpdate((dt, input) => {
    const dirX = (input.down("ArrowRight") ? 1 : 0) - (input.down("ArrowLeft") ? 1 : 0);
    const dirY = (input.down("ArrowDown") ? 1 : 0) - (input.down("ArrowUp") ? 1 : 0);
    move(dirX * speed * dt, dirY * speed * dt);   // stopped by anything solid, in the same step
  });
  return <Entity transform={{ x, y }}><Sprite image="hero.png" /></Entity>;
}

useBody is a box that moves a pixel at a time: add a <Tilemap solid> or a <Collider solid> to the level and move stops at it.

Movement is over time, so it reads the held keys in useUpdate, which gets the same input as useInput. Something that happens once, on a press (if (input.pressed("Z")) step();), goes in useInput. There is no need to copy keys into a useRef to carry them from one to the other.

Replace the <Sprite> with <Shape kind="rect" width={16} height={16} color="gold" /> to see a square, and back to see the sprite from assets/hero.png.

3. A sprite

Put a PNG in assets/ and name it: <Sprite image="hero.png" originX={8} originY={8} />. A missing image is a compile error (rge build checks the assets folder), not a magenta square at run time. A sheet of equal frames takes frameWidth, frameHeight and frame.

4. A sound

// src/effects.ts
import { createSounds } from "@rge/runtime";
export const sfx = createSounds({ beep: "beep.wav" });

// src/GameState.ts: call it from a game-state action
step: () => {
  sfx.play("beep");
  set((s) => ({ steps: s.steps + 1 }));
},

Put beep.wav in assets/. A sound is an effect, not state: playing it renders nothing and is counted, so a test can check it.

5. A second screen

// src/Main.tsx
<Router route={screen}>
  <Route name="title"><Title /></Route>
  <Route name="play">
    <Entity name="Hero" transform={{ x, y }}><Sprite image="hero.png" originX={8} originY={8} /></Entity>
  </Route>
</Router>

// src/GameState.ts: screen: "title" | "play", start: () => set({ screen: "play" })

Title is a component in src/Title.tsx that calls start() when Enter is pressed (useInput). Only the screen the router shows is in the world.

6. A test

// test/hero.test.ts
import assert from "node:assert/strict";
import { test } from "node:test";
import { render } from "@rge/testing";
import { Hero } from "../generated/Hero.ts";

test("holding right moves the hero its speed a second", () => {
  const t = render(Hero, {});                 // one component, no window
  const start = t.state().x as number;        // its own state, by the names in its source
  t.input("ArrowRight*60");                   // an input script: one second of holding right
  assert.equal(t.state().x, start + 120);
});

As React Testing Library tests one React component, render mounts one compiled component in a world with no window: step it, press keys, report collisions, and read its state and what it would draw (see Testing one component). To play the whole game, runScript(gameConfig, parseInputScript("Enter, _*3, right*30", { bindings }), observe) from @rge/player runs an input script on a recording backend; the template's test/play.test.ts does that.

7. Check it

npm run check

Compile, type-check, test, parity. A failing step prints its output and stops there.

8. Package it

npm run package                 # dist/my-game/: the game as one executable on Node's V8 (about 100 MB)
npx rge package --engine quickjs   # a few MB, on the Rust host, no JIT
npx rge package --headless         # the software renderer, no window: for CI

The folder holds the executable, lib/ (librge) and assets/; copy it anywhere and run it. Saves and settings (<Game id="...">, Saved data) go to the user's data folder.
