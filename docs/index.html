react-game-engineAuthoring guide and reference

Write games as components.

react-game-engine is a native-first 2D engine with React-like TSX authoring. There is no React and no virtual DOM. A compiler turns each component into an ordinary TypeScript class. Its children are persistent instances that are updated in place when state changes.

Component.tsxYour TSX: state, hooks, elements.
→
CompilerChecks the rules, lowers to an IR, emits a class.
→
Generated .tsOne class per component, committed next to an .ir.json.
→
PlayerRuns the frame loop, draws via raylib, reads input.

The mental model in five lines

  1. A component is a function with hooks, then one return of JSX. It is compiled, never executed as written.
  2. Its root element is a built-in (Entity, Sprite, Game…) and the generated class extends it.
  3. State is a snapshot, as in React. Setters batch into one render per frame.
  4. Position is state: transform={{ x, y }} on any element, usually driven by useState.
  5. Each frame runs useInput → useUpdate → render dirty components → commit structure → draw.

The rule of thumb. Anything outside the supported subset is a compiler diagnostic (RGE####), never silently ignored. If it compiles, it does what it says. See Error codes.

Components

A component is a top-level function declaration or const arrow with a capitalised name, optionally exported (one per module may be the default export, and it needs a name). Its body is, in this order:

  1. Hooks: useState, useRef, useSound, useGame(...), and the handler hooks.
  2. Derived values: const hurt = health < 25;. These are inlined where used, so JSX and handlers always see current state.
  3. One return of JSX.

An arrow with an expression body is just its return: const Dot = () => <Sprite image="dot.png" />.

The root is a built-in

The root element (or a fragment <>…</>, which is an implicit Entity) is a built-in and never another component. The generated class extends it, so the root's props apply to the component itself and its children become the component's children.

Because a component extends its root, its state, refs and props cannot reuse that built-in's member names (for example a prop called width on a Collider root, or name on an Entity root). The compiler tells you.

Imports

  • Hooks, built-in elements, clamp and the Child type come from "@rge/runtime/jsx". The type form is import { type Child }, the one place type is accepted.
  • Components come from "./Name.tsx", named or default (import Monster from "./Enemy.tsx"). No namespace imports, no as.
  • The game state comes from "./GameState.ts" — the only relative .ts import a component may have.
  • Imports are mandatory, as in React: using a hook or element without importing it is RGE1005.
  • Math is a global and needs no import.

Allowed in a component body

Allowed
  • Number, string, boolean, null literals
  • State and prop reads
  • Unary ! - +, binary arithmetic, comparison, logical
  • a ? b : c, parentheses, template literals
  • Array and object literals, with spreads
  • Member reads (e.id, items.length, found?.hp)
  • Non-mutating array methods (map, filter, some…)
Not allowed
  • Loops, try, let, await, this
  • Calling arbitrary functions
  • Text children and spread attributes in JSX
  • useEffect, ref={…}, useContext
  • Hooks inside conditions, loops or handlers
  • Passing the bare props object on or spreading it

Hooks

Hooks are top-level statements only (RGE1101 otherwise). A use* call that is not on this list is RGE1102. Every hook comes from @rge/runtime/jsx except useGame.

HookSignatureWhen it runs
useStateconst [v, setV] = useState(init)Render; setters batch into one render per frame
useRefconst r = useRef(0)Never renders; plain read and write of r.current
useInputuseInput((input) => …)Every frame, first
useUpdateuseUpdate((dt) => …)Every frame, after useInput
useMountuseMount(() => …)Once, when joining the world (children first)
useUnmountuseUnmount(() => …)Once, when leaving the world (parent first)
useSoundconst play = useSound("hit.wav")You call play() in a handler
useGameuseGame((s) => s.player.hp)Re-renders when that leaf changes

useState

  • Must be a top-level const [a, setA] = useState(...) (RGE1103).
  • The initial value is a constant or a prop (RGE1303).
  • Snapshot semantics. setN(n + 1); setN(n + 1) adds 1. setN((n) => n + 1) twice adds 2. All handlers in a frame see the same state whichever runs first.
  • Arrays and records are immutable. A setter only renders when given a new value, so never mutate items. useState([]) without a type is RGE1104.
  • The type you write (Spawn, Item | null) must be declared in the same file.

useRef

A primitive (number, string, boolean) that survives frames and never renders. Reach for it for things like the direction held this frame or a one-shot flag. Read and write .current only inside handlers.

Assignments allowed on a ref: =, +=, -=, *=, /=. Writing the same ref from two handlers in conflicting ways is RGE1404.

useInput and InputState

Input is polled each frame, not delivered as events. There are no onKeyDown props.

MemberTypeMeaning
input.pressed(key)booleanTrue only on the frame the key went down
input.down(key)booleanTrue while the key is held
input.released(key)booleanTrue only on the frame the key went up
input.pointerX, input.pointerYnumberMouse position

useUpdate

dt is the frame time in seconds, clamped to 0 – 0.1 so a stall cannot teleport things. The first frame's dt is 0. Always multiply speeds by dt.

useInput, useUpdate, useMount and useUnmount may each appear several times; they run in source order. A return; in one does not skip the others.

useMount / useUnmount

  • No cleanup function to return, and no useEffect. React to a change where the change happens.
  • A component mounts when it is attached to the world (a condition turning on, a list item added) and unmounts when detached. Each hook runs once per stay.
  • Takes one arrow function with no parameters.

useSound

Call the returned function as a statement in a handler. Calling it in JSX or a derived value is RGE1305. Sounds are preloaded when the window opens, so the first play does not hitch. Paths are relative to the <Game assets> folder.

What handler code may contain

Handlers (the bodies of the hooks above and of callback props) are lowered to a small statement language. It is deliberately narrow so the compiler can track state exactly.

Statements
  • Calling a setter: setX(5), setX((x) => x + 1)
  • if / else, early return
  • const locals
  • Ref assignment: r.current = …
  • Calling a sound function or a useGame action
  • Calling a callback prop: onDone?.()
Calls and members
  • Math.abs floor ceil round sign sqrt sin cos min max
  • clamp(value, min, max) (3 args)
  • input.pressed / down / released, input.pointerX / pointerY
  • other.tag, other.owner in collision callbacks
  • Template literals

Everything else (let, loops, try, other function calls, assigning to anything but ref.current) is RGE1301, RGE1401 or RGE1402. Position is never assigned: it is state.

Transform and drawing order

Every element except Game, Screen and a sound accepts transform. All fields are optional, and values may come from state.

FieldDefaultMeaning
x, y0Pixels, relative to the parent. y points down.
rotation0Radians. Positive turns clockwise.
scaleX, scaleY1Per-axis scale. Negative flips.
z0Draw order: higher is drawn later, so on top. Negative is behind. Adds to the parent's, so raising a component raises everything in it.
globalfalseTrue: the transform is in world space and ignores the parent.
  • Origin is the top-left corner of a Sprite, AnimatedSprite, Shape, Text, Collider, Pointer; rotation and scale are about it.
  • A child at { x: 10 } inside a parent at x: 100 is at 110 in the world, and turns and scales with the parent.
  • Equal z keeps tree order (parent first, then children in order). Ordering is global across the tree, not per parent.
  • On a component element, transform places the whole component. The component's props type never declares it.
  • A malformed transform, or one on an element with none, is RGE1207.

Props, callbacks and children

A component takes props through a destructured parameter annotated with a props type declared in the same file. A parent passes them as attributes. A changed value updates the existing child in place; the child is never recreated.

  • function Enemy(props: EnemyProps) also works: read props.speed, call props.onDefeated?.(). The bare props cannot be passed on or spread.
  • Defaults go in the destructuring (tint = "red").
  • Use callback props for child → parent messages. Call them with ?.() if optional.
  • A bad props parameter or a wrongly passed prop is RGE1208.

Passing children

Declare children: Child and say where they mount with {children}, once, as a direct child of a container (the root, a fragment, or a static <Entity> below it). The parent owns what it passes: elements are built from, and updated by, the parent's state.

Conditions and lists

JSX children are elements, conditionals or keyed lists. Text children, fragments inside children, and other expressions are RGE1202 (the one exception is text inside <Text>).

Conditionals

A condition turning off unmounts the child (useUnmount runs); turning on creates it and mounts it.

Keyed lists

Rule (otherwise RGE1209)
The source is a state or prop array, optionally followed by .filter((e) => …).
map takes one inline arrow (item, optionally index) returning exactly one element: an expression body, or a block with only return <X … />.
No conditionals, fragments or children inside the arrow. A richer item is a component.
The element has a key that reads the item (key={e.id}). A key reading only the index compiles with a warning; one reading neither is an error. key anywhere else is RGE1203.
A callback on the item may read the item but not the index.

Instances follow keys: adding, removing or reordering items mounts, unmounts and moves instances, and keeps each one's own state.

Game state: createGameState

useState is one component's own state. The game state belongs to the whole game (score, hit points, a mute switch) and is shaped like a Zustand store: you read with a selector, and you change it with actions that call set.

Rules

  • Selectors are plain paths (s.stats.coins) to a leaf. Naming an object is an error, and a typo gets a "did you mean" (RGE1108).
  • Call useGame(...) at the top level, bound with const to one name.
  • An action is called as a statement in a handler, not in JSX, a derived value, or a state updater.
  • set shallow-merges: a nested object is replaced whole, so spread the rest ({ ...s.stats, coins: … }).
  • Only components that read a leaf that changed re-render. A set that changes nothing renders nothing.
  • GameState.ts must be an arrow/function returning an object literal of number, string, boolean literals, nested objects of those, and top-level functions (actions). No arrays yet. Anything else is RGE1109.
  • useGame.getState() and useGame.setState(…) exist for non-component code (tests, tools).

useState or useGame? Use useState for what one component owns (its position, a flag). Use useGame for what several components must share, or what the HUD shows about the player.

Collisions and presses

There is no physics. The player finds boxes that start and stop touching and calls your callbacks. Collider is an axis-aligned box (top-left at the object's position, scaled and rotated by its world transform) that draws nothing. Pair it with a Shape to see it.

ConceptMeaning
other.tagThe other collider's tag ("" when none). Tells apart colliders on one prefab.
other.ownerThe name of the nearest <Entity name> at or above the other collider, or its component's class name. Tells apart prefabs.
layer / hitsA pair is tested only when each side's hits allows the other's layer. Use them to skip pairs cheaply (bullets ignore bullets). Unrelated to tag.
onCollisionExitFires once when a touching pair separates, or when the other leaves the world. It does not fire for a collider that itself left.
In a <Hud>Colliders never touch anything.

Handlers can read exactly tag and owner on other, nothing else.

Pointer presses

A left click goes to the topmost pressable (a Pointer or a Flex with onPress) under the mouse, in draw order. One press, one target; if the topmost misses, the one below is tried. A press inside a <Hud> uses HUD coordinates, so HUD buttons work however the camera moves.

UI, screen and camera

The shape of a game root

Layout with Flex

UI is laid out, not placed by hand. A <Flex> places its children in a row or column with CSS-flexbox props and Clay-style sizing. A child's own transform still moves it within its slot. Only a Flex is resized by layout; a Sprite, Shape or Text keeps its own size.

Size valueMeaning
"fit" (default)The children plus padding and gaps.
"grow"The fit size plus a share of the parent's free space.
120Fixed pixels.
"50%"A percentage of the parent's inner size.

Floating boxes (float) leave the flow and attach to a point of the parent with anchor, to, offsetX, offsetY, for tooltips and corner badges. Draw them above neighbours with z.

Screen: fixed resolution

fitBehaviour
"integer" (default)Largest whole-number scale that fits. Every game pixel is the same size. Bars fill the rest with border.
"contain"Largest scale that fits, fractional allowed.
"stretch"Each axis scaled on its own to fill the window.
"expand"Like "integer", but the game is widened to the window's shape. A wide window shows more world instead of bars. Lay out with grow and percentages, not fixed x positions.

Only the root's <Screen> does this, and it cannot be placed with transform. Everything inside is in game pixels: transforms, camera, mouse. Without a Screen, coordinates are window pixels.

Hud

A layer drawn after the world through a view that ignores the camera. Coordinates are screen pixels (game pixels under a Screen), top-left is 0, 0. Put it directly inside the game's root. Its transform moves the whole layer; z orders things inside.

Camera

  • It follows its children. <Camera><Player /></Camera> keeps the view on the player. With several children it centres on their middle. With no children it stays where it is.
  • The camera is transparent to its children's transforms: they are placed as if it were not there. Its own transform is an offset from the followed point.
  • zoom magnifies (2 = twice as large, must be positive).
  • The first camera in draw order is the view; a second is ignored with one warning. With no camera, the world origin is the window's top-left.

Scenes and prefabs

Every exported component is a prefab: the compiler records its name and props so data files can place it. A scene is JSON.

  • Callbacks cannot come from data, and children is passed, not set.
  • Children mount after the prefab's own children, or at its {children} slot if it renders one.
  • Validate with rge-compile src out --scenes scenes. Errors are RGE1501–RGE1509 with the exact JSON location.
  • Tiled .tmj maps in the scenes folder are imported to scene JSON automatically.
  • Exported names must be unique across files (RGE1206) since scenes refer to them by name.

How a frame works

  1. Presses. A new left click goes to the topmost Pointer / Flex onPress under the mouse.
  2. world.tick(dt, input): all useInput handlers, then all useUpdate handlers, then every dirty component renders once, then structural changes commit (conditions and list items mount and unmount).
  3. Draw. The tree is walked depth-first into draw records in tree order (or z order), with the camera applied.
  4. Collisions. New touching pairs call onCollisionEnter. Their effects render on the next tick.
  5. The backend draws and presents, then supplies next frame's input.

Consequences worth knowing

  • State set in a handler shows up next render, not immediately. Refs are the exception: read and write at once.
  • Things attached during a frame start getting hooks next frame; detached ones are skipped.
  • Many setters in a frame still cause one render. Animations (AnimatedSprite) cost no renders.
  • Unchanged subtrees reuse last frame's draw records, so a standing-still scene is cheap. Compiled components need nothing to benefit.
  • Assets that fail to load never crash: a missing image is drawn as a magenta 16×16 square, and an unreadable colour is magenta, each with one warning.
  • Colours are CSS: #rgb, #rgba, #rrggbb, #rrggbbaa, rgb(), rgba(), named colours, transparent.

Built-in elements

All built-ins are capitalised (there are no lowercase tags). Required props are marked required. Click an element to jump to it.

Error codes

The compiler reports RGE#### codes with source locations. Codes are stable and never renumbered.

Gotchas and tips

  • "Why is my game doing nothing?" Did you multiply by dt? Is the component actually mounted (inside the root, condition true)?
  • Two setX(x + 1) adds 1. Use the updater form.
  • Mutating array state does not render. Always create a new array.
  • Settings on <Game> are literals. width={640}, never state. <Game> is only ever a component's root.
  • HUD text follows state through <Text>Score: {score}</Text>; use text= or children, never both.
  • A collider that never fires? Check both sides' hits allow the other's layer, and that neither is under a <Hud>.
  • Pixel art blurry? smooth on <Game> is off by default (sharp). Use Screen fit="integer".
  • No full-screen key? F11 by default, and Alt + Enter always. fullscreenKey={false} turns the key off.
  • Debug a hitbox: put a semi-transparent Shape of the same size next to the Collider.
  • Commit the generated output after changing component source. CI fails on drift.
