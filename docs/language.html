react-game-engineAuthoring guide and reference

Components

A component is a top-level function or const arrow with a capitalised name, optionally exported (one per module may be the default, and it needs a name). Its body, in order:

  1. Hooks: useState, useRef, useSound, useGame(...), and the handler hooks.
  2. Derived values: const hurt = health < 25;, inlined where used.
  3. One return of JSX.

An arrow with an expression body is just its return: const Dot = () => <Sprite image="dot.png" />.

The root is a built-in

The root (or a fragment <>…</>, an implicit Entity) is a built-in, never another component. The class extends it, so the root's props apply to the component itself.

State, refs and props cannot reuse the root built-in's member names (a prop called width on a Collider root, name on an Entity root).

Imports

  • Hooks, elements, clamp and the Child type: from "@rge/runtime/jsx" (import { type Child }).
  • Components: from "./Name.tsx", named or default. No namespace imports or as.
  • Game state: from "./GameState.ts", the only relative .ts import allowed.
  • Imports are mandatory: an unimported hook or element is RGE1005.
  • Math needs no import.

Allowed in a component body

Allowed
  • Number, string, boolean, null literals
  • State and prop reads
  • Unary ! - +, binary arithmetic, comparison, logical
  • a ? b : c, parentheses, template literals
  • Array and object literals, with spreads
  • Member reads (e.id, items.length, found?.hp)
  • Non-mutating array methods (map, filter, some…)
Not allowed
  • Loops, try, let, await, this
  • Calling arbitrary functions
  • Text children and spread attributes in JSX
  • useEffect, ref={…}, useContext
  • Hooks inside conditions, loops or handlers
  • Passing the bare props object on or spreading it

Hooks

Hooks are top-level statements only (RGE1101). Any other use* call is RGE1102. All come from @rge/runtime/jsx except useGame.

HookSignatureWhen it runs
useStateconst [v, setV] = useState(init)Render; setters batch into one render per frame
useRefconst r = useRef(0)Never renders; plain read and write of r.current
useInputuseInput((input) => …)Every frame, first
useUpdateuseUpdate((dt) => …)Every frame, after useInput
useMountuseMount(() => …)Once, when joining the world (children first)
useUnmountuseUnmount(() => …)Once, when leaving the world (parent first)
useSoundconst play = useSound("hit.wav")You call play() in a handler
useGameuseGame((s) => s.player.hp)Re-renders when that leaf changes

useState

  • Form: top-level const [a, setA] = useState(...) (RGE1103). The initial value is a constant or a prop (RGE1303).
  • State is a snapshot. setN(n + 1) twice adds 1; setN((n) => n + 1) twice adds 2.
  • Arrays and records are updated immutably: a setter renders only for a new value. They need a type declared in the same file; useState([]) is RGE1104.

useRef

A number, string or boolean that persists across frames and never renders. Read and write .current only in handlers.

Allowed: =, +=, -=, *=, /=. Conflicting writes to one ref are RGE1404.

useInput and InputState

Input is polled each frame. There are no key-event props.

MemberTypeMeaning
input.pressed(key)booleanTrue only on the frame the key went down
input.down(key)booleanTrue while the key is held
input.released(key)booleanTrue only on the frame the key went up
input.pointerX, input.pointerYnumberMouse position

Key names (an unknown name warns once and never fires):

useUpdate

dt is the frame time in seconds, clamped to 0–0.1 (0 on the first frame). Multiply speeds by it.

Each handler hook may appear several times; they run in source order.

useMount / useUnmount

  • No cleanup return and no useEffect.
  • Mounts when attached to the world (a condition turns on, a list item is added); unmounts when detached.
  • Takes one arrow function with no parameters.

useSound

Call it as a statement in a handler (elsewhere is RGE1305). Paths are relative to <Game assets>. Sounds preload, so the first play does not hitch.

What handler code may contain

Handlers (hook bodies and callback props) use a small, deliberately narrow subset:

Statements
  • Calling a setter: setX(5), setX((x) => x + 1)
  • if / else, early return
  • const locals
  • Ref assignment: r.current = …
  • Calling a sound function or a useGame action
  • Calling a callback prop: onDone?.()
Calls and members
  • Math.abs floor ceil round sign sqrt sin cos min max
  • clamp(value, min, max) (3 args)
  • input.pressed / down / released, input.pointerX / pointerY
  • other.tag, other.owner in collision callbacks
  • Template literals

Anything else (let, loops, try, other calls, assigning to anything but ref.current) is RGE1301, RGE1401 or RGE1402.

Transform and drawing order

Every element except Game and Screen accepts transform. All fields are optional and may come from state.

FieldDefaultMeaning
x, y0Pixels, relative to the parent. y points down.
rotation0Radians. Positive turns clockwise.
scaleX, scaleY1Per-axis scale. Negative flips.
z0Draw order: higher is drawn later, so on top. Negative is behind. Adds to the parent's, so raising a component raises everything in it.
globalfalseTrue: the transform is in world space and ignores the parent.
  • Origin is the top-left corner of a Sprite, AnimatedSprite, Shape, Text, Collider, Pointer; rotation and scale are about it.
  • Children are relative: x: 10 inside a parent at x: 100 is at 110, and turns and scales with the parent.
  • Equal z keeps tree order, globally across the tree.
  • On a component, transform places the whole component; do not declare it in the props type.
  • A malformed transform is RGE1207.

Props, callbacks and children

Props come through a destructured parameter typed with a props type declared in the same file. A changed value updates the child in place; it is never recreated.

  • props: EnemyProps also works (props.speed), but props cannot be passed on or spread. Defaults go in the destructuring.
  • Callback props carry child → parent messages. Call optional ones with ?.().
  • A bad props form is RGE1208.

Passing children

Declare children: Child and place {children} once, directly inside a container (the root, a fragment, or a static <Entity>). The parent owns what it passes and updates it from its own state.

Conditions and lists

JSX children are elements, conditionals or keyed lists. Anything else (text, other expressions) is RGE1202, except text inside <Text>.

Conditionals

A condition turning off unmounts the child; turning on mounts it.

Keyed lists

Rule (otherwise RGE1209)
The source is a state or prop array, optionally followed by .filter((e) => …).
map takes one inline arrow (item, optionally index) returning exactly one element: an expression body, or a block with only return <X … />.
No conditionals, fragments or children inside the arrow. A richer item is a component.
The element has a key that reads the item (key={e.id}). A key reading only the index compiles with a warning; one reading neither is an error. key anywhere else is RGE1203.
A callback on the item may read the item but not the index.

Instances follow keys, so each keeps its own state as items move.

Game state: createGameState

The game state is shared by every component (score, hit points) and shaped like a Zustand store: read with a selector, change with actions that call set.

Rules

  • Selectors are plain paths to a leaf (s.stats.coins); an object or a typo is RGE1108. Call useGame(...) at the top level, bound to a const.
  • Call an action as a statement in a handler, not in JSX or a derived value.
  • set shallow-merges: a nested object is replaced whole, so spread the rest ({ ...s.stats, coins: … }).
  • Only components reading a leaf that changed re-render.
  • GameState.ts must return an object literal of number, string and boolean literals, nested objects of those, and top-level action functions. No arrays yet (RGE1109).
  • useGame.getState() / setState() work outside components (tests, tools).

useState or useGame? useState for what one component owns; useGame for what several share or the HUD shows.
